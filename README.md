# AI Resume–Job Matcher

**Start here:** see [`START_HERE.md`](START_HERE.md) for the exact Windows setup sequence.

A production-style full-stack application that compares a PDF resume against a job description and produces an explainable, evidence-based match report.

## 1. Problem

Candidates often receive opaque resume scores that do not explain *why* they match a job or what evidence is missing. This project combines deterministic extraction, normalized skills, semantic embeddings, configurable weighted scoring, and optional LLM-generated explanations.

## 2. Features

- PDF resume upload with validation and safe temporary processing
- Job description parsing into required/preferred skills, technologies, education, experience, soft skills, and domain requirements
- Resume parsing into skills, technologies, education, experience, projects, certifications, and achievements
- Skill normalization (e.g. `CPP` → `C++`, `JS` → `JavaScript`, `ML` → `Machine Learning`)
- Semantic similarity using `sentence-transformers/all-MiniLM-L6-v2`
- Explicit weighted scoring: required skills, preferred skills, semantic relevance, experience alignment, and project relevance
- Evidence attached to skill matches and gaps
- Project-to-job relevance analysis
- Evidence-based resume improvement suggestions
- Optional LLM explanations and suggestions through an OpenAI-compatible endpoint
- PostgreSQL history storing report metadata/JSON only; raw resumes are not stored
- Demo mode that works without an API key
- Responsive SaaS-style React dashboard
- Backend validation, error handling, tests, and a small evaluation dataset

## 4. Matching methodology

The system uses multiple signals:

1. **Required skill coverage** — weighted coverage of required JD skills.
2. **Preferred skill coverage** — coverage of preferred JD skills.
3. **Semantic relevance** — cosine similarity between resume evidence and the JD.
4. **Experience alignment** — extracted years/role/domain evidence compared with the JD.
5. **Project relevance** — semantic + skill overlap for resume projects.

Related skills are normalized through an explicit alias/group map. The system does not treat arbitrary keywords as equivalent.

## 5. Scoring methodology

Default weights are configurable in `backend/app/config.py`:

- Required skills: 40%
- Preferred skills: 15%
- Semantic relevance: 20%
- Experience alignment: 15%
- Project relevance: 10%

The final score is the weighted sum of normalized component scores. Every component is also returned in the report so the result can be inspected and reproduced.

## 6. AI usage

- **Embeddings** are used for semantic similarity, skill equivalence, and project relevance.
- **Structured extraction** is primarily deterministic for transparency and to keep demo mode independent of an API key.
- **Optional LLM** is used only for natural-language explanations, summaries, and recommendations. It can be enabled by configuring an API key and model.

## 7. Setup

### Prerequisites

- Node.js 20.19+ (Vite currently requires Node 20.19+ or 22.12+)
- Python 3.12+ (3.11+ should also work)
- Docker Desktop (recommended for PostgreSQL)

### Start PostgreSQL

```bash
docker compose up -d db
```

### Backend

```bash
cd backend
python -m venv .venv
# Windows PowerShell
.venv\Scripts\Activate.ps1
# macOS/Linux
# source .venv/bin/activate

pip install -e .
copy .env.example .env   # Windows CMD
# cp .env.example .env  # macOS/Linux

uvicorn app.main:app --reload --port 8000
```

The first semantic analysis may download the Sentence Transformers model if it is not already cached. A small deterministic similarity fallback keeps demo/testing usable when the embedding package or model is unavailable.

### Frontend

```bash
cd frontend
npm install
npm run dev
```

Open the URL printed by Vite, usually `http://localhost:5173`.

## 8. Running locally

1. Start PostgreSQL with `docker compose up -d db`.
2. Start FastAPI on port 8000.
3. Start Vite on port 5173.
4. Use **Try demo analysis** on the home page to verify the full UI immediately.
5. For a real PDF, upload the PDF and paste a JD, then choose **Analyze Match**.

The backend will reject non-PDF uploads and files above the configured size limit.

## 9. Testing

Backend tests:

```bash
cd backend
pytest
```

The evaluation set is in `backend/sample_data/evaluation.json`.

## Data and privacy notes

The API extracts text in memory and removes the temporary upload after parsing. PostgreSQL stores the analysis report and metadata, not the original uploaded PDF. History entries can be deleted through the API/UI.

## Environment variables

See `backend/.env.example`.

The LLM integration is optional. Without an LLM key, the application still performs extraction, normalization, embeddings, scoring, evidence mapping, project relevance, and deterministic recommendations.
